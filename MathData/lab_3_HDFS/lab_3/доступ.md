# Доступ к стенду: портал, VPN, SSH

Один раз на весь семестр. Если вы уже заходили на `node1` — переходите к лабе.

### 0.1. Получите доступ на портале

Преподаватель выдаёт вам **код приглашения** — он одноразовый и работает
только один раз.

1. Откройте портал: **<https://stand.37.230.233.211.nip.io/>**
2. Введите код, фамилию с именем и отчеством и учебную группу.
3. Подтвердите согласие на обработку персональных данных.
4. На странице выдачи вы увидите **логин и временный пароль** — они
   показываются один раз, запишите их сразу.
5. Скачайте архив. Он тоже выдаётся один раз.

Логин формируется автоматически из ваших данных и выглядит так:
`ivanov_ii_bvt-16-3`. Повторно зарегистрироваться не получится: тот же
человек получит то же имя, а оно уже занято.

Адрес выглядит непривычно, но это обычный сайт с настоящим
сертификатом — предупреждений о безопасности быть не должно.
**Если браузер всё же предупреждает — не продолжайте**, а сообщите
преподавателю: значит вы попали не туда.

### 0.2. Что в архиве

| Файл | Назначение |
|---|---|
| `<логин>.ovpn` | профиль VPN |
| `id_ed25519`, `id_ed25519.pub` | пара ключей SSH, публичная половина уже загружена на сервер |
| `ПАМЯТКА.txt` | тот же порядок действий, что и здесь |

### 0.3. VPN

Кластер находится во внутренней сети и снаружи не виден.

Клиент OpenVPN:

- Windows — <https://openvpn.net/community-downloads/>
- macOS — <https://tunnelblick.net/downloads.html>
- Linux — пакет `openvpn` из репозитория дистрибутива

Импортируйте профиль и подключитесь. **Спросит имя пользователя
и пароль** — это ваши логин и пароль со страницы выдачи.

Проверка:

```bash
ping -c 2 node1.mtuci.cloud.ru
```

Прописывать имена в `/etc/hosts` **не нужно** — DNS выдаётся через VPN.

**Если вы проходили этот курс раньше — наоборот, проверьте и удалите
старые записи.** Прежняя версия работы предписывала прописывать адреса
вручную, а стенд с тех пор переехал. Такие записи перекрывают DNS,
и имя будет вести на несуществующий адрес, хотя по IP всё работает.

```
Windows:        C:\Windows\System32\drivers\etc\hosts
Linux и macOS:  /etc/hosts
```

Одна учётная запись — одно подключение. Если войти под тем же логином
со второй машины, первое подключение оборвётся.

### 0.4. Ключ SSH и вход

Сначала распакуйте архив. **В Windows** двойной щелчок в проводнике
не подходит — он открывает только внешний слой. Откройте PowerShell
в папке с загрузкой:

```powershell
tar -xzf <ваш_логин>.tar.gz
```

В Linux и macOS — то же самое командой `tar -xzf`.

#### Windows

Клиент `ssh` встроен в Windows 10 и 11, ставить ничего не нужно.

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
Copy-Item id_ed25519, id_ed25519.pub "$env:USERPROFILE\.ssh\"
```

Теперь права. Windows не использует `chmod`, а OpenSSH отказывается
работать с ключом, доступным другим пользователям, и пишет
`bad permissions`. Снимаем наследование прав и оставляем доступ только себе:

```powershell
icacls "$env:USERPROFILE\.ssh\id_ed25519" /inheritance:r
icacls "$env:USERPROFILE\.ssh\id_ed25519" /grant:r "$env:USERNAME:(R)"
```

Файл настроек:

```powershell
Add-Content -Encoding ascii "$env:USERPROFILE\.ssh\config" @"
Host *.mtuci.cloud.ru
    User <ваш_логин>
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
"@
```

Кодировка `ascii` указана намеренно: файл в UTF-8 с меткой порядка байтов
OpenSSH не понимает и молча игнорирует.

#### Linux и macOS

```bash
mkdir -p ~/.ssh
cp id_ed25519 id_ed25519.pub ~/.ssh/
chmod 700 ~/.ssh && chmod 600 ~/.ssh/id_ed25519
```

Добавьте в `~/.ssh/config`:

```
Host *.mtuci.cloud.ru
    User <ваш_логин>
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

#### Зачем `IdentitiesOnly yes`

На сервере ограничено число попыток входа. Если у вас уже есть другие
ключи, агент переберёт их первыми и исчерпает лимит раньше, чем дойдёт
до нужного: вход завершится отказом, хотя ключ верный. Это самая частая
причина обращения «ключ не работает».

#### Вход

```bash
ssh <ваш_логин>@node1.mtuci.cloud.ru
```

Команда одинакова во всех системах. Если файл настроек создан, флаги
не нужны; иначе укажите ключ явно:

```bash
ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes <ваш_логин>@node1.mtuci.cloud.ru
```

### 0.5. Смените пароль

Пароль один на всё: VPN, SSH и веб-интерфейсы стенда. Выданный —
временный, смените его при первой возможности:

```bash
kinit <ваш_логин>
```

Минимум 12 символов, три класса: буквы разных регистров, цифры,
спецсимволы. Забытый пароль сбрасывает только преподаватель.
