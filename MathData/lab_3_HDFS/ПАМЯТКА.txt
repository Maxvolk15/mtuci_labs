Доступ к учебному стенду МТУСИ

Логин: aralushkin_md_bvt-24-2
Пароль вам показан на странице выдачи. Здесь он не хранится.


1. VPN

   Импортируйте aralushkin_md_bvt-24-2.ovpn в клиент OpenVPN.
   При подключении спросит имя пользователя и пароль — это ваши
   логин и пароль от стенда, а не что-то отдельное.

   Windows: https://openvpn.net/community-downloads/
   macOS:   https://tunnelblick.net/downloads.html
   Linux:   пакет openvpn из репозитория дистрибутива

   Без поднятого VPN не работает ничего из дальнейшего.


2. КЛЮЧ SSH — WINDOWS (PowerShell)

   Выполняйте в папке, где лежат файлы из архива.

       New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
       Copy-Item id_ed25519, id_ed25519.pub "$env:USERPROFILE\.ssh\"

   Теперь права. Windows не использует chmod, а OpenSSH отказывается
   работать с ключом, который доступен кому-то ещё, и пишет
   "bad permissions". Снимаем наследование и оставляем доступ только себе:

       icacls "$env:USERPROFILE\.ssh\id_ed25519" /inheritance:r
       icacls "$env:USERPROFILE\.ssh\id_ed25519" /grant:r "$env:USERNAME:(R)"

   Файл настроек:

       Add-Content -Encoding ascii "$env:USERPROFILE\.ssh\config" @"
       Host *.mtuci.cloud.ru
           User aralushkin_md_bvt-24-2
           IdentityFile ~/.ssh/id_ed25519
           IdentitiesOnly yes
       "@

   Кодировка ascii указана намеренно: файл в UTF-8 с меткой порядка
   байтов OpenSSH не понимает.

   Клиент ssh встроен в Windows 10 и 11, ставить ничего не нужно.
   Проверить: ssh -V


3. КЛЮЧ SSH — LINUX И macOS

       mkdir -p ~/.ssh
       cp id_ed25519 id_ed25519.pub ~/.ssh/
       chmod 700 ~/.ssh
       chmod 600 ~/.ssh/id_ed25519

   Добавьте в ~/.ssh/config:

       Host *.mtuci.cloud.ru
           User aralushkin_md_bvt-24-2
           IdentityFile ~/.ssh/id_ed25519
           IdentitiesOnly yes


4. ЗАЧЕМ IdentitiesOnly yes

   На сервере ограничено число попыток входа. Если у вас уже есть
   другие ключи, агент переберёт их первыми и исчерпает лимит раньше,
   чем дойдёт до нужного. Вход завершится отказом, хотя ключ верный.


5. ВХОД

       ssh aralushkin_md_bvt-24-2@node1.mtuci.cloud.ru

   Если имя не разрешается, а по IP-адресу всё работает — проверьте
   файл hosts: от прежних курсов там могли остаться записи со старыми
   адресами, и они перекрывают DNS, выдаваемый через VPN.
       Windows: C:\Windows\System32\drivers\etc\hosts
       Linux и macOS: /etc/hosts

   Если файл настроек из пунктов 2 или 3 создан, флаги не нужны.
   Иначе укажите ключ явно:

       ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes aralushkin_md_bvt-24-2@node1.mtuci.cloud.ru


6. СМЕНИТЕ ПАРОЛЬ

       kinit aralushkin_md_bvt-24-2

   Пароль один на всё: VPN, SSH и веб-интерфейсы стенда.
   Выданный — временный. Забытый пароль сбрасывает только преподаватель.
